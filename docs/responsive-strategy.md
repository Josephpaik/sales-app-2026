# 반응형 화면 분할 전략

현장 영업(모바일/태블릿)과 사내 영업관리(PC 웹)는 업무 특성이 다르므로 **하나의 웹에서 기기에 따라 분할 전략을 다르게** 가져간다.

## 1. 기기 판정

`src/hooks/useDevice.ts`

| 기기 | 폭 | 레이아웃 | 시연 강제 |
|---|---|---|---|
| phone | < 768px | `MobileLayout` · 1단 | `#/…?device=phone` |
| tablet | 768 ~ 1199px | `MobileLayout` · 최대 2단 (`.m-body.split`) | `?device=tablet` |
| desktop | ≥ 1200px | `DesktopLayout` · 3단 이상 (Splitter) | `?device=desktop` |

라우트는 동일하고(`App.tsx`), 각 페이지가 `useDevice()`로 렌더링 방식을 고른다.

## 2. 현장 영업 (antd-mobile)

| 요소 | 컴포넌트 | 적용 화면 |
|---|---|---|
| 서랍식 메뉴 | `Popup position="left"` + `List` | 전체 (NavBar 좌측 ☰, TabBar "더보기") |
| 하단 탭 | `TabBar` (대시보드·영업 건·고객사·계약·더보기) | 전체 |
| 2단 분할(태블릿) | CSS grid `minmax(300px, 38%) 1fr` — 왼쪽 목록 / 오른쪽 상세 | 영업 건, 고객사, 계약 |
| Bottom Sheet | `Popup position="bottom"` | 조회 조건, 영업 건 빠른 등록, 활동 기록, 고객사 빠른 등록, 사용자/역할 |
| 상태 전이 | `ActionSheet` (허용 전이만 노출) | 영업 건 상세 |
| 진행 단계 | `Steps` (발굴→진행→수주→이행→종결) | 영업 건 상세 |
| 빠른 입력 | `Selector`(큰 터치 칩), `Stepper`, `TextArea` | 등록 시트 |
| 전화 걸기 | `<a href="tel:">` (마스킹 표시, 열람 시 감사 로그) | 고객 담당자 |

설계 원칙: 필수 항목만 입력받고 상세 항목(팀·담당·파트너·라인)은 PC에서 보완한다. 등록 후 바로 상세로 이동해 활동 기록을 이어 갈 수 있게 한다.

## 3. 사내 영업관리 (antd)

| 단 | 내용 | 컴포넌트 |
|---|---|---|
| 1단 | 전체 네비게이션 (역할별 메뉴) | `Layout.Sider` + `Menu` (접기 가능) |
| 2단 | 파이프라인·실적 대시보드 / 목록 + 집계 행 | `Table`(정렬·페이지·`scroll.x`), KPI 카드 |
| 3단 | 세부 필터 / 상세 미리보기·정산 내역 | `Splitter.Panel`(폭 조절·접기), `Descriptions`, `Tabs` |

- 영업 건: `[조회 조건] | [목록·집계] | [상세]` — 목록 행 클릭 시 URL(`/sales/:id`)이 바뀌고 3단에 상세가 표시된다(브라우저 뒤로가기·공유 가능).
- 고객사: `[조회 조건] | [마스터] | [360° 뷰]`
- 계약: `[목록] | [상세]`, 공통코드: `[그룹] | [코드]`
- 등록·수정은 `Modal` + `Form`(자동 계산: 매출액·부가세·이익률), 대량 검토는 집계 행(건수·매출·매입·이익·확도가중·수주잔고)과 CSV 내보내기.

## 4. 공통 규칙

- 업무 규칙은 UI가 아니라 `src/api/index.ts`에 둔다: 상태 전이 허용표, 교차검토 경고, 데이터 범위, 마스킹·열람 로그.
- 모바일에서 편집 권한이 없는 역할(재무·MA·경영진)은 조회 전용으로 동작한다.
- 후속 항목(문서번호·지급상태·시리얼)은 화면에 "(후속)" 표기만 하고 입력을 받지 않는다.
